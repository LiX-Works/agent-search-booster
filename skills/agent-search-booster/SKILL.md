# Agent Search Booster

用户提出任务，本Skill统一调度搜索与资料获取工具。目标是扩大普通搜索的来源覆盖，并取得更完整、可分析的正文、帖子、评论与文档。工具组合和调用方法已在附属文件中给出，使用者准备好依赖后直接调用；不要把工具选择和每一步操作交回用户。

## 调用路线

按任务选择相应路线，只加载所需说明。以下是同一工具组合的分工，不是要求用户逐项选插件，也不要求每题调用全部工具。

| 任务或缺口 | 调用工具 | 读取 |
|---|---|---|
| 普通搜索遗漏来源，需跨语言、域名或时间检索 | 内置搜索、Exa、Tavily、SearXNG | [网页与MCP调用](references/web-tools.md) |
| 已找到网页，但只能看到摘要或正文不全 | 原页/浏览器、Exa fetch、Trafilatura、Firecrawl、Jina Reader | 网页与MCP调用 |
| 搜索小红书、Reddit、YouTube、知乎等平台，读取正文、回复或字幕 | OpenCLI、Browser Bridge、当前浏览器 | [平台调用](references/platforms.md) |
| 追查X原帖、线程、观点变化及相关网页 | Grok CLI | [Grok调用](references/grok.md) |
| 软件库、SDK、代码和仓库讨论 | Context7、官方文档、GitHub CLI | 网页与MCP调用 |
| 取得的材料是PDF、Office、扫描件，或需读取RSS | MarkItDown、Docling、FreshRSS | [本地材料与服务](references/local-tools.md) |
| 需要批量阅读、独立分析或审查 | 可用原生子代理或AGY；有subagent-manager时沿用其规则 | [协作衔接](references/collaboration.md) |

学术选文、正式论文PDF及OpenAI产品问题，衔接当前可用的专用Skill；该路由不替代出版方来源要求或官方文档核验。

## 在任务中执行

- 结合主题、资料类型和缺口选择路线；查询词、语言、时间范围、结果数量和组合可以调整。重要疑点继续追查，新增材料主要重复时收束。
- MCP使用实际暴露的工具schema；CLI使用当前子命令帮助。发现来源后继续取得任务所需内容，不停在标题列表或搜索摘要。
- 搜索列表、页面正文、评论、字幕是不同材料。读取分页和必要回复，记录实际覆盖；全文/完整评论的请求需要核对终点与截断，无法取得的部分如实说明。
- 连接报错先小范围确认入口、浏览器桥或错误类型，再恢复当前链路或换工具。不要无目标重装、重复登录或循环重试。关键证据缺失或严重冲突时暂停相关结论并集中询问，其他工作继续。
- 初次准备或缺少工具时，读[工具清单](references/tool-catalog.md)与[必要配置](references/setup.md)，指出缺项影响。已有可用入口复用；缺少一项可以使用现有能力推进并说明缺口，不声称已启用完整组合。普通任务不重复全套检查。

## 交付与操作范围

结果应回答用户问题，保留必要来源和未决项。原文核验、时效及操作边界见[执行规则](references/operating-rules.md)，不每次复制成警告清单。安装与配置不等于实际获取成功；辅助模型和多个模型共识也不替代来源。

Skill提供统一调用指引，MCP、CLI、账户和浏览器连接仍需在运行环境可用。运行中可按[经验记录](references/experience.md)积累可迁移的成功方法、故障与回退路径；不把一次结果自动升为永久规定。
