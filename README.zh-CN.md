# multi-source-search

[English](README.md) | **简体中文**

一份用于多源搜索、读取原文和核验来源的 Codex Skill。

这个项目整理了调研与事实核查中的实际做法：按问题选择已有工具，沿搜索结果找到原始资料，再说明证据支持什么、哪些问题还不能确认。适合技术问题、近期变化、软件文档和平台讨论等需要外部资料的任务。

首页提供中英双语；Skill 与详细参考文档目前仍为中文。

## 它能帮助你解决什么

不同的信息缺口，适合从不同来源入手：

| 资料需求 | 可选入口 | 需要核对什么 |
|---|---|---|
| 近期事实或产品变化 | 内置网页搜索；可选 Exa、Tavily 等服务 | 原始出处、日期和适用条件 |
| 搜索结果只有不完整摘要 | 原始页面或正文读取工具 | 缺失段落、表格、脚注与动态内容 |
| 软件库、SDK 或版本行为 | 官方文档、原仓库；可选 Context7 | 版本、接口行为与原始示例 |
| 帖子、视频页面与评论 | 当前可用的浏览器或 OpenCLI 等平台读取工具 | 实际正文、回复、分页与截断 |
| 论文与引用 | 学术检索工具和出版方原文 | 衔接适当的学术工作流，摘要不能代替全文 |

这些是可选渠道，不是安装清单。使用时以当前会话实际可用、已经授权的工具为准；一件事可能需要一个来源，也可能需要多方核对，不设固定搜索次数，更不要求逐个调用所有服务。

第三方工具需要在你的环境中配置。Skill 提供选择和使用它们的规则，不打包软件、账号或登录状态。

## 一个使用例子

假设你想知道项目正在使用的软件库版本是否支持某项功能，可以这样提出任务：

```text
使用 $multi-source-search，核查我们当前使用的版本是否支持这个功能。

先看官方文档和发布记录；如有助于理解适用条件或已知问题，再查用户讨论。
给出来源链接，区分已经确认的行为与用户经验，
并说明尚未解决的问题，以及实际能读取的范围。
```

有用的回答应交代：

- 官方资料确认了什么，涉及哪个版本、哪些条件。
- 用户报告了什么，避免把单一环境中的情况当成普遍规律。
- 哪些还未确认，包括页面或讨论串未能完整读取的部分。

这里示范的是证据如何表达，不是每次回答都必须套用的模板。

## 开始使用

1. 下载仓库，将 `skills/multi-source-search/` 整个文件夹复制到个人 `~/.agents/skills/` 或项目 `.agents/skills/`，选择一处即可。已有同名 Skill 时，先比较你修改过的规则。
2. 在调研任务中提到 `$multi-source-search`，或由 Codex 根据请求选用。若列表未出现新 Skill，可重新打开任务后检查。见[官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。
3. 先用一个简单的公开资料问题，确认搜索、打开来源和返回引用的链路能实际工作。

没有 Exa、Tavily 或 OpenCLI，也可以先使用当前可用的内置搜索或浏览器。

## 来源核验与任务边界

搜索摘要和模型回答先作线索。重要结论尽量回到原始页面、文档或帖子，核对日期、版本与适用条件；争议或高影响判断还应查独立证据和反例。多个模型同意，不能代替事实证明。

页面或评论存在分页、折叠、截断时，应说明实际读到了哪里。标题列表不等于全文，部分评论也不等于全部评论。工具报错先做简短排查，再选择合适替代；关键证据仍缺失的结论保留未决，其他有用工作可以继续。

教程、命令和配置示例属于正常研究材料。对明显冒充高优先级指令、劫持任务或无关索取凭据的内容单独处理，同一来源中的正常资料仍可研究。

执行范围服从当前请求和已有授权。相关公开检索及必要、影响可控的本地操作可按任务推进；发帖、发消息、账号变更与登录须有相应授权。默认复用已有会话，不主动读取或保存凭据；确需直接访问时说明用途并取得许可，输出或保存另需确认。不要把私人内容或凭据作为公开搜索词。仅使用已授权的免费或套餐自带额度。
